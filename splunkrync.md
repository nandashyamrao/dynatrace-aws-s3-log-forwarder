# Splunk rsync Pipeline – Dry Run & Secure SSH Setup

This document explains how the GitLab pipeline pushes CSV lookup files to Splunk using `rsync`, how **dry run mode** works, and how **Splunk admins must generate and store SSH keys securely in AWS Secrets Manager**.

---

## 🧪 What Is “Dry Run Mode”?

**Dry run mode = simulate the pipeline without making real changes**

In this pipeline, it means:

- ✅ Verify SSH authentication
- ✅ Validate network connectivity
- ✅ Confirm correct Splunk host selection
- ✅ Confirm file paths and rsync command
- ❌ **Do NOT copy files to Splunk**

---

## 🔍 In Plain English

> “Show me what you *would* do — don’t actually do it.”

Dry run ensures the pipeline is correct **before touching Splunk PROD**.

---

## 🎯 Why Dry Run Is Critical

Dry run allows you to safely validate:

- Correct SSH private key
- GitLab runner → Splunk connectivity
- Firewall / routing issues
- Hostname correctness
- rsync syntax

**No data is transferred. No Splunk impact.**

---

## 🛠 How rsync Dry Run Works

rsync supports a native flag:

```bash
--dry-run

Example:

rsync -avz --dry-run splunk/servicenow.csv splunk2@host:/opt/splunk/var/

Expected output:

sending incremental file list
servicenow.csv

Nothing is copied.

⸻

🧩 Dry Run in the GitLab Pipeline (YAML-Safe)

Step 1 — Pipeline Variable

variables:
  DRY_RUN: "true"   # set to "false" to enable real transfer


⸻

Step 2 — Conditional rsync Logic

RSYNC_FLAGS="-avz"

if [ "$DRY_RUN" = "true" ]; then
  RSYNC_FLAGS="$RSYNC_FLAGS --dry-run"
  echo "⚠️ DRY RUN ENABLED — no files will be copied"
fi

rsync $RSYNC_FLAGS splunk/servicenow.csv \
  "$SPLUNK_USER@$SPLUNK_HOST:$SPLUNK_DEST_DIR/"

This syntax is GitLab YAML–friendly and safe.

⸻

🧠 What Dry Run Validates

Area	Checked
ssh-agent	✔ Key loads
DNS	✔ Host resolves
Firewall	✔ Port 22 reachable
Auth	✔ SSH accepted
Paths	✔ Destination exists
rsync	✔ Command correctness
Splunk	❌ No file modified


⸻

🚨 What Dry Run Does NOT Do

❌	Reason
Copy file	Disabled by design
Refresh lookup	No file write
Prove write permissions	Needs real transfer
Detect disk-full	Requires write

A single real run is still required after validation.

🔐 Splunk Admin Instructions – SSH Key Generation

These steps must be performed by the Splunk Admin team

Step 1 — Generate SSH Key Pair (on Splunk host)

ssh-keygen -t rsa -b 4096 -f splunk_gitlab_rsync -C "gitlab-rsync"

This creates:
	•	splunk_gitlab_rsync (private key)
	•	splunk_gitlab_rsync.pub (public key)

⸻

Step 2 — Install Public Key on Splunk

mkdir -p /home/splunk2/.ssh
chmod 700 /home/splunk2/.ssh
cat splunk_gitlab_rsync.pub >> /home/splunk2/.ssh/authorized_keys
chmod 600 /home/splunk2/.ssh/authorized_keys

Validate:

ssh -i splunk_gitlab_rsync splunk2@<splunk-host>


⸻

🔑 Store Private Key in AWS Secrets Manager

Private key must never be committed to Git

Step 3 — Create Secrets

Create two secrets (recommended):
	•	splunk2_ssh_key_test
	•	splunk2_ssh_key_prod

Secret value (JSON format):

{
  "ssh_private_key": "-----BEGIN RSA PRIVATE KEY-----\n...\n-----END RSA PRIVATE KEY-----"
}

Ensure:
	•	Newlines preserved (\n)
	•	No extra spaces

⸻

Step 4 — GitLab CI Variables

Set GitLab masked variables:
	•	SPLUNK2_SSH_KEY_PRIVATE_TEST
	•	SPLUNK2_SSH_KEY_PRIVATE_PROD

These values are read and loaded into ssh-agent.

⸻

🔐 ssh-agent Loading Logic (Pipeline)

eval "$(ssh-agent -s)"
mkdir -p ~/.ssh
chmod 700 ~/.ssh

if [ "$SPLUNK_ENV" = "PROD" ]; then
  echo "$SPLUNK2_SSH_KEY_PRIVATE_PROD" | tr -d '\r' | ssh-add -
else
  echo "$SPLUNK2_SSH_KEY_PRIVATE_TEST" | tr -d '\r' | ssh-add -
fi

This ensures:
	•	Correct key per environment
	•	No plaintext keys on disk
